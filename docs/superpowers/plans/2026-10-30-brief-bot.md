# brief-bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Telegram-бот, который проводит пользователя по сценарию из PDF и отдаёт заявку менеджеру, с визуальным редактором сценария для заказчика и напоминанием о брошенной анкете.

**Architecture:** Модульный монолит: FastAPI и aiogram-polling в одном процессе, домены `scenario`, `dialog`, `leads`, `access`. Сценарий хранится данными, чистая функция `step()` обходит граф, адаптеры Telegram, Redis и Postgres подключены через порты. Редактор: Nuxt 4 SPA с Vue Flow поверх HTTP API.

**Tech Stack:** Python 3.13, uv, aiogram 3, FastAPI, dependency_injector, asyncpg, redis-py, pytest, Docker Compose, Postgres, Redis, Nuxt 4, Pinia, `@vue-flow/core` 1.48.2, `@dagrejs/dagre`, vitest, Caddy.

**Spec:** `docs/superpowers/specs/2026-10-30-brief-bot-design.md`. Макет: `design/shared/project/`, предпросмотр `design/preview/`. Сценарий: `~/Downloads/document.pdf`.

## Global Constraints

- Слои бэкенда: точка входа → usecase → service → порт ← адаптер. Пропускать слои нельзя (`clean-backend-architecture`, `clean-backend-monolith`). Telegram, HTTP и таймер являются точками входа.
- Слои фронтенда: page/component → composable → store → repository port ← adapter (`clean-frontend-architecture`).
- Зависимости доменов: `dialog` → `scenario`, `dialog` → `leads`. `scenario` и `leads` друг о друге не знают.
- `callback_data` не длиннее 64 байт. Id шагов и опций: `[a-z0-9_]`, не длиннее 24 символов.
- Менеджерский чат задаётся только переменной `TELEGRAM_MANAGER_CHAT_ID`. Ни в редакторе, ни в API этой настройки нет.
- Секреты через `SecretStr`, настройки только через `BaseSettings`, логи: постоянное сообщение плюс скаляры в `extra`, без телефонов и имён.
- Комментарии и пользовательские тексты на русском. Копирайт редактора берётся из макета дословно.
- Каждый шаг "Commit" это отдельный коммит. Без `Co-Authored-By: Claude` и без упоминаний Claude. Push только с разрешения Алексея: remote нет.
- Изменение домена обновляет `docs/services/<domain>/` в том же коммите, изменение экрана обновляет `docs/frontend/` и артборд в том же коммите. Перед первым таким изменением загрузить `clean-backend-documentation` и `clean-frontend-documentation`.
- VK, MAX, симулятор диалога, аналитика и роли в этот план не входят.

## Review Focus

1. Пользователь пишет текст, когда бот ждёт кнопку: бот повторяет текущий экран, ответ не засчитывается. Тест в Task 4.
2. `/start` посреди анкеты: бот спрашивает "Продолжить" или "Начать заново", ответы не теряются. Тест в Task 8.
3. Двойное нажатие той же кнопки мультивыбора: `message is not modified` от Telegram не роняет обработчик. Тест в Task 8.
4. Telegram недоступен или заявка длиннее 4096 символов: заявка уже лежит в БД, сообщение разбивается на части, сбой отправки не показывается пользователю. Тест в Task 7.
5. Редактор открыт в двух вкладках: устаревшее сохранение черновика отклоняется, а не затирает новое. Тест в Task 10.
