# scenario: инварианты

| Правило | Где держится |
|---|---|
| Сохранение черновика не теряет незнакомые поля шага, кнопки и верхнего уровня | store хранит объекты как пришли, `extra` держит лишние поля верхнего уровня; `toDraftData()` собирает всё обратно. Тест `незнакомые поля … доживают до сохранения` |
| Кнопка получает ровно один порт, id порта равен id кнопки; выход самого шага называется `:next` | [toFlow](../../../editor/app/utils/scenarioGraph.ts); id шага и кнопки не содержит `:`, коллизии нет |
| Список из более чем 5 кнопок сворачивается в 3 строки и "ещё N кнопок"; порты свёрнутых кнопок остаются на строке "ещё", рёбра не теряются | `rowsOf` в `scenarioGraph.ts` |
| Шаг без кнопок, которому нужен переход (`text`, `file`, `multi`, `multi_input`, любой с `next`), получает строку-выход: "Ответ текстом", "Файл", `done_label` или "Готово", "Далее" | `rowsOf` |
| Главный граф: шаги, достижимые от `entry`, не заходя в блок ни входом `call`, ни прямым переходом на первый шаг блока | `stepsOf` |
| Вкладка блока: шаги, достижимые от его первого шага без `@return`, кроме шагов главного графа и первых шагов других блоков | `stepsOf` |
| Шаг, который не показывает ни один вид, попадает в главный граф и не пропадает с экрана | `stepsOf`; на сиде таких нет |
| Виды не исключают друг друга по шагам, но на сиде не пересекаются: главный граф 55, `sections` 7, `sphere` 2, `site_examples` 1, `final` 5, всего 70 | тест `сид: все шаги видны хотя бы в одном виде` |
| Вход в блок рисуется одной нодой на пару (блок, `then`); выход ноды ведёт на `then` | `callFor` |
| Переход на шаг вне вида, на `@return` или на несуществующий id рисуется заглушкой: "Переход на шаг", "Выход из блока", "Нет такого шага"; заглушка одна на цель | `stubFor` |
| Раскладка dagre считается только по прямым рёбрам: рёбра, замыкающие цикл (поиск в глубину), не ранжируют ноды | `cycleEdgeIds`, `autoLayout` |
| Ребро, чья цель не правее источника, рисуется тонким и светлым (класс `back`); при выборе ноды её обратные рёбра темнеют | `markBackEdges`, `useScenarioLayout`, стили в [ScenarioGraph](../../../editor/app/components/ScenarioGraph.vue) |
| Начальный вид большой схемы: начало сценария в масштабе не меньше 80%, остальное зумом и миникартой; малая схема (до 14 нод) вписывается целиком | `focus` в `ScenarioGraph.vue` |
| Круг `load` → `toDraftData` на сиде возвращает `scenario.json` без потерь; каждая кнопка и `next` сида даёт ребро хотя бы в одном виде | тесты на сиде |
| Шаги с `pos` стоят на своём месте, остальные получает dagre; "Разложить" очищает `pos` шагов текущего вида, шаги других видов не трогает | `autoLayout`, `store.clearPositions`, `useScenarioLayout.relayout` |
| Размеры ноды берутся из артборда: ширина 190, шаг `26 + 46 + 28 * строк + 6`, блок и заглушка 64; раскладка и отрисовка используют одни и те же числа | константы в `scenarioGraph.ts`, тест на отсутствие наложений на сиде |
| Перетаскивание ноды пишет `pos` (целые числа) в шаг и уходит в черновик вместе с остальными правками | `useEditStep.moveStep`, `ScenarioGraph` (`node-drag-stop`) |
| Каждая правка делает новый объект `steps` (и шага, и кнопки, которых она коснулась); порядок шагов и незнакомые поля сохраняются; старые объекты не меняются | действия store, тест `правки не меняют прежние объекты...` |
| Id шага `s_` и 8 символов a-z0-9, id кнопки `o_` и 8 символов; не совпадает с занятыми; `s:<шаг>:o:<кнопка>` не длиннее 64 байт (25) | `freshId` в store, тест `test_add_option_generates_short_id` |
| Начальный шаг (`entry`) удалить нельзя: кнопка в панели неактивна, `removeStep` возвращает false | `useEditStep.canRemove`, `store.removeStep` |
| Удаление шага чистит ссылки на него: `next` шага и кнопок, `then` входа в блок, `back_to`, `when` шага и кнопок (условие снимается), записи `blocks`; ссылки на сам блок (`call`) остаются, валидатор покажет их при публикации | `detach` в store, тест `test_remove_step_clears_references` |
| Шаг, с которого начинается общий блок, удаляется только с подтверждения | `useEditStep.removeStep` |
| Удаление кнопки убирает её id из `any` и `none` чужих условий; условие без отметок (`any` и `none` пусты) снимается, а условие с пустым `any` и непустым `none` остаётся, панель просит выбрать ответ. То же при снятии последней отметки | `store.removeOption`, `withoutAnswer`, `useEditStep.setAnswer` |
| Ссылка на сайт и переход кнопки взаимоисключают друг друга: побеждает последнее заданное. Режим ссылки определяет наличие ключа `url`: пустая строка остаётся строкой и поле адреса не исчезает; "Открыть ссылку на сайт" ставит `url: ""`. Валидатор backend считает пустой `url` отсутствием перехода (`missing_next`) | `store.updateOption`, [validator.py](../../../backend/src/scenario/validator.py) |
| Кнопка получает "Куда ведёт" только у выбора, сообщения и завершающего шага; "Снимает другие отметки" только у "Несколько ответов" и "Несколько + поле"; "Человек вводит свой текст" только у "Несколько + поле" | `StepPanel` (`buttonsLead`, `multiButtons`, `ownText`) |
| Условие показа шага и кнопки редактирует один компонент: вопрос, `any`, `none`; подсказка о пустом `any` называет шаг или кнопку | [WhenField](../../../editor/app/components/WhenField.vue), `useEditStep.whenOf`, `setCondition`, `setAnswer` с `optionId` |
| Концом анкеты шаг делает только `finish`, переключатель недоступен у текста и файла. Уже стоящий признак можно снять, иначе ошибку `bad_finish` не исправить | `canFinish` в [stepType.ts](../../../editor/app/utils/stepType.ts), `StepPanel` (`finishLocked`) |
| Новый шаг создаётся с текстом "Новый шаг": пустой текст не прошёл бы публикацию | `store.addStep` |
| Выбор без подписи ответа показывает подсказку "Без подписи ответ не попадёт в заявку."; у остальных типов с ответом подписи требует публикация (`missing_key`) | `StepPanel` (`keylessChoice`) |
| Подпись кнопки не длиннее 40 знаков (счётчик и `maxlength`) | `StepPanel` |
| Неподключённый шаг, созданный на вкладке блока, виден на этой вкладке до подключения; после перезагрузки он в главном графе | `homes`, `stepsOf` |
| Сохранения идут по очереди: правка во время запроса уходит после ответа с новой `revision`, ревизии не пересекаются | `store.flush`, тест `правка во время сохранения...` |
| Автосохранение: тишина 800 мс, один запрос на серию правок | `useAutosaveDraft`, тест `test_autosave_debounced` |
| Публикации предшествует сохранение черновика; если оно не удалось, публикации нет | `store.publish`, тест `не публикует, если черновик не сохранился` |
| Ошибки публикации сбрасываются только следующей успешной публикацией или загрузкой, правка их не сбрасывает | `store.publish`, тест `ошибки живут до следующей успешной публикации...` |
| Панель ошибок есть только на схеме: при 422 со страниц "Заявки", "Настройки", "Версии" редактор переходит на `/` со снятым выбором шага. Если сценарий ещё не загружен, он читается до перехода и ошибки возвращаются в store: первая загрузка на схеме их не сотрёт | `usePublishScenario` (`showIssues`) |
| Номер ошибки на ноде равен номеру в панели; ошибка кнопки помечает шаг кнопки; ошибка блока (`stepId` это имя блока) ведёт на вкладку блока, `malformed` без перехода | `errorNumbers`, `locateIssue` |
| После конфликта (409) правки не принимаются: схема не двигается, палитра неактивна | `store.touch`, `ScenarioGraph` (`locked`) |
| Подписи `name` и `Направление` использует бот (`{name}` в текстах, направление заявки): шаг с такой подписью показывает её по-человечески ("Имя", "Направление") и не редактируется; новую подпись нельзя сделать равной `name` или `Направление`, правка не применяется, под полем подсказка | [stepKeys.ts](../../../editor/app/utils/stepKeys.ts), `useEditStep.setKey`, тест `нельзя сделать подпись равной name...` |
| Подпись, которая встречается как `{подпись}` в тексте другого шага, и подпись-дубль дают предупреждение под полем (со ссылкой на шаг), правка разрешена | `keyInfo`, [StepPanel](../../../editor/app/components/StepPanel.vue) |
| Смена типа шага чистит скрытое: `text`, `file` без кнопок; `choice` без `input`, `exclusive` и `next` шага; `multi`, `multi_input` без `next` у кнопок (у шага берётся `next` первой кнопки, если своего нет); `multi` без `input`; `validate` только у `text`; `key` не у `info`. Если пропадают кнопки или переходы, сначала вопрос с числом, отказ ничего не меняет | [stepType.ts](../../../editor/app/utils/stepType.ts) (`convertStep`), `store.changeStepType`, `useEditStep.changeType` |
| Пока шаг не подключён ни одной стрелкой (кроме начального и первого шага блока), панель пишет "Шаг пока не подключён. Бот его не покажет." | `isConnected` в [stepTargets.ts](../../../editor/app/utils/stepTargets.ts) |
| При конфликте (409) все поля панели заблокированы (`fieldset disabled`), кнопка удаления тоже | `StepPanel` |
