# dialog: инварианты

Код: [engine.py](../../../backend/src/dialog/engine.py), [entities.py](../../../backend/src/dialog/entities.py).

## Переходы

| Правило | Детали |
|---|---|
| `step()` не бросает исключений на чужие события | событие `button`/`done`/`back` с `event.step`, не равным `session.step` (старая кнопка), возвращает тот же экран без эффектов |
| Переход разворачивает цель в показываемый шаг | `Call` кладёт `then` в стек и идёт в начало блока; `@return` берёт со стека; шаг с невыполненным `when` пропускается по его `next`. Предел 1000 разворотов, дальше считается концом анкеты |
| `@return` при пустом стеке или цепочка без шага | анкета заканчивается на текущем шаге, `finished = True`, эффект `FINISHED`; экран остаётся прежним |
| Шаг "терминальный" | `finish = True` либо `info` без опций и без `next` |
| Вход в терминальный шаг ставит `finished` и эффект `FINISHED` | у `info` без опций и `next` экран без кнопок и без "Назад" |
| `finished`-сессия не реагирует ни на что | кроме кнопки `finish`-шага |

## Финал с кнопками (`finish`)

- Вход в `finish`-шаг: `FINISHED`, `can_back = False`, кнопки (видимые по `when`) остаются на экране.
- Кнопка под финалом (с `next`, без `url`) начинает новый проход: `answers`, `returns` и `reminded` очищены, `finished` сброшен, `chat_id`, `version` и `username` сохранены. Версия не обновляется: проход идёт на закреплённой версии.
- `history` нового прохода пуст, если у финала нет `back_to` или кнопка ведёт прямо на `back_to`. Иначе `history = (back_to,)` с пустыми снимками, и "Назад" на первом шаге прохода возвращает на `back_to`.
- Этот переход может сразу прийти в терминальный шаг: тогда `FINISHED` и `finished = True`.

## История и "Назад"

| Правило | Детали |
|---|---|
| Три списка параллельны | `history`, `history_returns`, `history_answers` одной длины; любая запись в `history` добавляет снимки |
| Снимок ответов это ключи, а не значения | на момент ухода с шага `history[i]`, с собственным ответом шага |
| `back` восстанавливает шаг, стек возврата (из `history_returns[-1]`) и оставляет в `answers` только ключи из `history_answers[-1]` | ответы брошенной ветки и ответ шага, с которого вернулись, исчезают из будущей заявки (их ключей нет в снимке) |
| `back` недоступен при пустой истории и на шаге с `no_back` | ответ тот же экран |
| Повторный приход на шаг, уже лежащий в пути, обрезает историю до его первого вхождения | это удерживает "Назад" от зацикливания; два захода в один блок на одном пути режут историю глубже, чем нужно (сид так не ходит) |
| Ожидание текста опции (`pending_input`) | "Назад" в это время отменяет опцию: убирает её из `answers` и снимает ожидание, шаг тот же. Прочие события, кроме текста, игнорируются. Экран ожидания всегда с `can_back = True` |

## Ответы

| Правило | Детали |
|---|---|
| Ключ шага `key` задаёт имя поля заявки; шаг без `key` в заявку не попадает | |
| Повторный выбор в `choice` перезаписывает ответ | |
| `exclusive` опция снимает все остальные, а выбор обычной опции снимает `exclusive` | `multi`, `multi_input` |
| `multi`-ответ без отметок удаляется целиком | |
| `multi_input`: текст опции хранится в `texts[option_id]`, снятие опции удаляет текст | |
| Подстановка `{ключ}` в текст берёт ответы `text`-шагов по `key`; неизвестный ключ остаётся как есть | `_fill` |
| `validate: phone` | не меньше 10 цифр, только цифры, пробелы, скобки, `+`, `-` |
| `validate: url` | начинается с `http://` или `https://`, либо содержит точку и не содержит пробелов |
| Ошибка проверки не меняет сессию | экран получает текст ошибки перед обычным текстом, эффектов нет |
| Пустой после обрезки текст игнорируется | |

## Экран

- `can_done`: `multi`, `multi_input`, а также `info` без опций со `next`.
- `done_label`: `Step.done_label`, иначе "Продолжить" у `info`, иначе "Готово".
- `edit = True` только у обычной отметки `multi`/`multi_input`: запрос текста опции приходит новым сообщением.
- `expects`: `text` у `text`-шага и при ожидании текста опции, `file` у `file`-шага.

## Хранение сессии

| Правило | Детали |
|---|---|
| Сессия лежит JSON-ом, `Session` в нём это объект, `Answer` словарь | [adapters/redis.py](../../../backend/src/dialog/adapters/redis.py) |
| Чтение возвращает кортежи в `history`, `returns`, `history_returns`, `history_answers`, `Answer.labels`, `Answer.ids`, а `Answer` как dataclass | иначе `Session` не равна исходной (`list != tuple`) и кортежи в движке (`+`, срезы) ломаются |
| Старый JSON без `history_answers` или `history_returns`, или с более короткими, дополняется до длины `history`: снимки ответов текущими ключами `answers`, снимки стека пустыми | "Назад" не падает и не стирает заявку; стек возврата для таких сессий теряется (пустой), ответы брошенной ветки в старой сессии не отсекаются |
| TTL сессии 30 дней, обновляется каждым `save` | |
| Очередь напоминаний: `schedule` сдвигает срок существующей записи | время должно быть с часовым поясом: срок хранится как `timestamp()` |
| `due(now, limit)` забирает записи: выдаёт чат ровно одному вызову, даже при параллельных тиках | Redis: `ZRANGEBYSCORE`, затем `ZREM` по каждому, в результат попадают только те, у кого `ZREM` вернул 1. Новое `schedule` после `due` создаёт новую запись, поэтому пользователь, нажавший кнопку после выдачи, получит новое напоминание. Обработчик, упавший после `due`, теряет напоминание (повторной выдачи нет) |
| Блокировки нет: два одновременных события одного чата дадут последний `save` | `HandleEvent` обязан сериализовать обработку одного чата |
