# dialog: сбои зависимостей

Исходящие вызовы: Telegram Bot API (ответы человеку) и, через `LeadService`, запись заявки и уведомление менеджера (см. [leads](../leads/FAILURE_MODES.md)). Хранилища сессий (redis) и сценария (postgres) тоже зависимости.

| Сбой | Поведение | Где |
|---|---|---|
| `TelegramBadRequest "message is not modified"` при правке сообщения | Проглатывается: экран уже такой | [render.py](../../../backend/src/bootstrap/telegram/render.py) |
| Сообщение нельзя править (`can't be edited`, `message to edit not found`, `no text in the message to edit`) | Вместо правки отправляется новое сообщение | там же |
| Иная ошибка правки (чат не найден, сеть, 5xx) | Пробрасывается в обработчик ошибок роутера | там же |
| Не удалось снять клавиатуру у нажатого сообщения | `logger.warning("Keyboard removal failed")`, новое сообщение всё равно отправляется. Ловится только `TelegramBadRequest` | там же |
| Исключение в обработчике (любой слой) | [handle_error](../../../backend/src/bootstrap/telegram/router.py): `logger.error("Update handling failed")` с `chat_id` и трассировкой, человеку «Что-то пошло не так. Попробуйте ещё раз.»; сбой самой отправки этого ответа логируется и глотается. Апдейт считается обработанным, повторной доставки нет | там же |
| Версии сессии нет в базе (восстановлен дамп старше последней публикации) | Шаг анкеты падает с `NotFound`, человек видит фразу об ошибке. `/start` и "Продолжить" показывают новую анкету на текущей версии (`DialogService.screen`), при ответах сначала экран возобновления. Ответы такой сессии потеряны | [services.py](../../../backend/src/dialog/services.py) |
| Запись заявки упала в `finish` | Исключение уходит выше, сессия не сохранена и остаётся на прежнем шаге: нажатие можно повторить; человек видит фразу об ошибке | [handle_event.py](../../../backend/src/dialog/usecases/handle_event.py) |
| Сбой уведомления менеджера | До диалога не доходит: `LeadService` его логирует, человек получает финальный экран | [leads](../leads/FAILURE_MODES.md) |
| Сбой redis при чтении или записи сессии | Исключение до обработчика ошибок; человек получает фразу об ошибке; состояние зависит от того, что успело записаться (заявка пишется до сессии) | |
| Фоновый опрос упал (неверный токен, сеть дольше backoff) | `logger.error("Polling stopped")`; приложение и `/health` остаются живыми, бот молчит. Перезапуска опроса нет | [app.py](../../../backend/src/bootstrap/app.py) |
| Пользователь заблокировал бота (`TelegramForbiddenError`) или чата нет (`TelegramBadRequest "chat not found"`) при напоминании | [TelegramChatGateway](../../../backend/src/bootstrap/telegram/gateway.py) бросает `ChatBlocked`; `SendReminders` пишет `INFO`, напоминание не считается отправленным. Частичная заявка менеджеру и `reminded = True` уже записаны | [send_reminders.py](../../../backend/src/dialog/usecases/send_reminders.py) |
| Сбой обработки одного чата в `SendReminders` (заявка, redis, отправка) | `logger.error("Reminder failed")` с `chat_id` и трассировкой; остальные чаты обрабатываются. Запись уже снята с очереди, повтора нет | там же |
| Сбой всего прохода напоминаний (например, redis недоступен в `due`) | [run_reminders](../../../backend/src/bootstrap/jobs/reminders.py): `logger.error("Reminder pass failed")`, цикл продолжается через 60 с. `CancelledError` завершает задачу | там же |
| Запись `settings.reminder` испорчена (не объект, `hours` не целое больше нуля, `text` не непустая строка) | [AsyncpgSettingsRepository](../../../backend/src/dialog/adapters/asyncpg.py): `logger.warning("Reminder settings are corrupted, defaults used")`, возвращаются значения по умолчанию; ход пользователя не падает | там же |
| Нет опубликованной версии сценария | `NotFound` из `ScenarioService.current`; `EnsureSeeded` в `lifespan` этого не допускает на чистой базе | |

## Остаточные случаи

| Случай | Что видно | Почему так |
|---|---|---|
| Процесс остановлен или чат упал после `due`, до отправки | Напоминание потеряно: запись с очереди снята. Следующее действие человека поставит новый срок (если `reminded` ложно) | `due` атомарно забирает записи ради отсутствия дублей; повторной выдачи нет |
| `LeadService.save_partial` в напоминании упал | Напоминание не уходит, `reminded` остаётся ложным; человек получит новое при следующем содержательном ходе | Заявка важнее напоминания: без неё напоминание не отправляется |
| Сбой отправки (не `ChatBlocked`) после `reminded = True` | Напоминание не повторяется для этой анкеты | Флаг ставится до отправки: лучше пропустить напоминание, чем слать дубли |
| Заявка записана (`LeadService.finish`), а сохранение сессии упало | Сессия осталась на прежнем шаге; повторное нажатие проходит финал ещё раз и создаёт вторую заявку (`full` не перезаписывается) и второе уведомление менеджеру | Заявка пишется раньше сессии, чтобы не потерять её; транзакции между postgres и redis нет. Дубль выбран вместо потери |
| Шаг сохранён, а ответ в Telegram не дошёл (сбой сети, исключение при отправке) | Сессия уже на новом шаге, человек видит старый экран; ошибка логируется, человеку уходит фраза об ошибке, если Telegram доступен. Повторное нажатие старой кнопки показывает текущий экран (`event.step` не совпадает) | Сессия сохраняется до отправки; повторной доставки апдейта нет. Выход: `/start` показывает текущий шаг или экран возобновления |

Команды (сообщения, начинающиеся с `/`, кроме `/start`) ответом анкеты не считаются: роутер превращает их в пустой текст, движок повторяет текущий экран, сессия не меняется.
